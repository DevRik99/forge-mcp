# Reglas duras — qa-master

| Regla | Verificación | Script o ruta | Qué previene |
|-------|-------------|---------------|--------------|
| `.only` / `.skip` / `fit` / `fdescribe` nunca commiteados | linter | `playwright/no-focused-test`, `playwright/no-skipped-test`, `vitest/no-focused-tests`, `vitest/no-disabled-tests` | tests excluidos silenciosamente del run — la suite reporta verde mientras deja de cubrir código |
| Ningún `waitForTimeout()` / sleep hardcodeado en tests E2E | linter | `playwright/no-wait-for-timeout` | la causa más común de flakiness (~45% según la propia skill) — esperar un tiempo fijo en vez de una condición real |
| Toda aserción async lleva su `await` | linter | `playwright/missing-playwright-await`, `testing-library/await-async-utils`, `testing-library/await-async-queries`, `vitest/valid-expect` | un test que "pasa" sin haber esperado el resultado real — falso positivo silencioso, el más peligroso porque no lanza error |
| Selectores basados en accesibilidad (rol, label, texto), nunca CSS anidado, XPath o IDs generados | linter | `playwright/no-raw-locators`, `testing-library/prefer-screen-queries` | tests que se rompen con cualquier cambio de maquetación aunque el comportamiento no haya cambiado |
| Todo test tiene al menos un `expect` real | linter | `vitest/expect-expect` | tests que ejecutan código pero no verifican nada, dando falsa sensación de cobertura |
| Cobertura configurada por archivo/glob (`perFile`), no sólo un umbral global agregado | script | lectura de `coverage.thresholds` en `vitest.config.ts`, falla si sólo existe un umbral global; verificado por `templates/check-coverage-thresholds-per-file.mjs` | código nuevo del PR sin ningún test, oculto detrás de archivos históricos bien cubiertos |
| El score de mutación tiene un umbral de corte en CI | script | configuración `thresholds.break` de Stryker, el pipeline corta si el score cae por debajo; verificado por `templates/check-mutation-score-threshold.mjs` | tests que ejecutan el código pero no detectan cuando el comportamiento cambia (suite en verde sin protección real) |
| El comando de verificación del proyecto incluye el schema-check de `.ai/feature_list.json` | script | lectura del JSON: rechaza más de una feature `in_progress` o un `status` fuera del enum válido; verificado por `templates/check-feature-list-schema-check-wired.mjs` | estado de features incoherente que nadie detecta porque el schema-check no corre |
| Existe un smoke test que arranca el sistema real (no sólo pruebas unitarias en verde) | script | comprobación de presencia de un smoke test que levanta el proceso y comprueba una ruta representativa, no sólo la raíz; verificado por `templates/check-smoke-test-exists.mjs` | una suite de miles de tests en verde mientras la aplicación real está caída (caso documentado: 1681 tests verdes, 17 horas de 500 en producción) |
| Que un test de integración realmente pruebe colaboradores reales y no sólo mocks (over-mocking) | no automatizable | — un linter no puede distinguir "integration test legítimo con 1-2 mocks de borde" de "test que sólo verifica que se llamó al mock"; requiere revisión manual | tests que dan 100% de cobertura con la aplicación completamente rota |
| `expect(true).toBe(true)` disfrazado de assert real (aserción trivial sobre una constante) | no automatizable | — ningún plugin de lint investigado distingue "literal constante" de "valor derivado que en este caso es constante" (declarado explícitamente en la skill) | tests que ocupan tiempo de CI sin verificar absolutamente nada |
